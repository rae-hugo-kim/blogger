## 경험치 2배 이벤트와 Claude의 멘붕

경험치사용량 2배 이벤트 기간이 되면서 Claude Opus가 영 정신을 못 차리고 있어요. 5시간에 토큰 털리는 양이 심상찮아서, 간만에 GPT-4랑 같이 병렬로 협업 아닌 협업을 좀 했네요.

현재 작업 중인 하네스는 아직 배포할 생각 없이 스스로 쓰려고 만들고 있는 상태라, 이름은 임시로 [claude](https://github.com/rae-hugo-kim/claude)입니다.

## 왜 커스텀 하네스를 만들게 됐나요?

작년 11월에 코딩도 AI도 아예 처음 접했어요. 당시 선풍적인 인기를 끌던 'claude.md' 작성법과 Kent Beck의 몇 가지 철칙이 아주 강렬하게 뇌리에 남았죠.

그 이후 저희 팀의 전반적인 작업 지향은 **spec-driven 개발을 하되 전 과정을 자동화한다**에 가깝게 잡혔고, Kent Beck의 TDD(테스트 주도 개발)와 Tidy Code 원칙을 상당히 적극적으로 수용하게 됐어요.

### 구조화의 필요성

처음엔 claude.md 문서 하나만으로 작업했지만, 완벽한 컨트롤이 힘들더라고요. 그래서:

- 폴더 트리를 구조화하고
- 구조에 맞는 claude 문서를 계층화하고
- 문서 간 상호 참조를 명백히 하는

방향으로 발전시켰어요.

동료들이 opencode나 warp 같은 다른 CLI를 사용할 때도, 저는 **Cursor + Claude Code CLI** 조합을 좀 고수했어요. 다양한 최신 툴을 옮겨다니는 대신, harness라는 시스템을 이해하고 내 작업 방향과 지향에 맞는 명령어(skill)와 claude 문서를 꾸미는 쪽을 선택했거든요.

## 하네스의 철학과 구조

기본적으로 Claude Code CLI를 사용하며 OMC를 쓴다는 걸 전제하고, OMC의 조금 자유로운 규율 위에 **강제적으로 TDD와 spec-driven을 엮어낸 규칙**을 덮었어요.

일부 스킬들은 OMC에서 업데이트되거나 추가되면서 중복 기능을 탑재하고 있거나 (깃헙 관리 스킬을 단축명령어로 만든 `compush`, `compr` 같은 skill), 일부 개발자분들이 이미 세션 기록을 피지컬 문서화해서 기록하는 걸 쉽게 하기 위해 작성한 서머리 작성 스킬(`sum`) 등이라 대단히 유니크한 하네스라고 생각하진 않아요.

다만 **편의성과 구조 강제**에 좀 더 중점을 두고 있다고 이해해 주시면 좋을 것 같아요.

## Spec-Driven + TDD의 핵심: kickoff-startdev 흐름

바이브코딩으로 코딩을 처음 하셨거나, 진지하게 오래 코딩하는 건 이쪽이 처음이신 경우 대부분 **작은 것은 잘 만들다가 큰 것을 만들 때 잘 안 되는 경험**을 하셨을 거예요.

당연한 일이죠. 투두앱, 캘린더앱 등 초보들이 한 개씩은 다 만드는 그 앱들은 완결적으로 코드 학습할 수 있는 샘플이 많이 존재하니까요.

하지만 조금만 복잡한 기능을 가진 나만의 앱을 구현하려고 하면 헛짓거리를 하게 돼요. "투두앱 만들어줘, 세련된 디자인으로" 같은 나이브하고 열려있는 요청으로도 구현 가능한 아주 작고 뻔한 앱이 아니니까요.

### PRD 문서의 중요성

이 경우 우리는 누군가 경험이 풍부한 선배가 "너는 이런 걸 정해야 앱을 개발할 수 있다"는 지침을 줄 필요가 있어요.

저는 그것을 별도의 도구로 분리해 PRD 문서를 아주 명확하고 자세하게, 심지어 코딩의 수준에 준하게 작성하려고 오랜 기간 삽질을 해봤어요. 그 흔적이 PRDchat이라는 웹앱으로도 남아있고요.

그 정도는 과하지만, 그래도 **정해야 할 것은 정해야 개발이 이뤄지고 개발이 잘 됐는지 점검도 할 수 있다**는 사실은 변함이 없어요.

### kickoff-startdev 스킬 흐름

그걸 해주는 게 `kickoff` → `startdev`로 이어지는 개발 시작 과정의 스킬 흐름입니다:

1. **kickoff**를 통해 이번 개발에서 구현할 것과 나중에 구현할 것의 scope를 나누고
2. 각 task 중 무엇이 MVP에 속하는지를 정하고
3. 이 프로젝트 전체의 **single source of truth**, 또는 그것에 준하는 1등급 인풋 문서로 존재할지 만들어줘요

## 추가 기능들

외에는 사용하면서 유용하다고 느꼈던:

- 컨텍스트7이나 세레나 같은 MCP를 기본적으로 탑재
- 최근에는 코드 리뷰 스킬도 괜찮은 걸 주워와서 추가할 생각

## 황견적 프로젝트 근황

황견적은 Claude가 멍청해지고 Gemini가 그림을 못 그리는 관계로 잠시 휴업 상태예요. 위에서 언급한 코드 리뷰 스킬을 이용해서 점검하는 데 그쳤고, 그나마도 토큰이 쑥쑥 빠져서...

며칠에 걸쳐서 다양한 부분을 좀 손보고 있어요. 확장 버전이 라이트 버전과 달리 그림도 많고 자료도 많다 보니 로딩이 쳐지는 부분이 있어서, 백이랑 프론트를 어떻게 연결할지, 로딩을 줄일 수 없을지 공부하고 있어요.

Redis를 이용해서 조금 서브 타임을 줄일 수 있다고 하는데, 확실히 이해하진 못해서 좀 더 봐야 할 것 같아요.
