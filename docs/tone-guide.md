# 블로그 톤 & 형식 가이드 (공통)

이 문서는 초안을 블로그 톤에 맞게 퇴고할 때 참조하는 **공통 기준**입니다. 퇴고는
사람 또는 에이전트가 대화형으로 수행합니다 (2026-07 refine AI 자동 재작성 퇴역).
문체 규칙은 글 종류에 따라 세 가이드로 분리되어 있습니다.

## 톤 선택

문체는 프론트매터 `categories`로 결정됩니다 — 퇴고 주체가 해당 문체 가이드를 컨텍스트로 로드해 적용합니다:

| categories | 문체 가이드 | 문체 | 해당 글 |
|---|---|---|---|
| `에세이` 포함 | [`tone-essay.md`](tone-essay.md) | 담백한 1인칭 서술체 (~했다/~이다) | 이세계 표류기 시리즈, 회고 에세이, 게임리뷰 |
| `특허` 포함 | [`tone-essay.md`](tone-essay.md) | 서술체 공유 (당분간 전용 가이드 없음) | 특허 실무 기록, 특허 프로젝트 연재 |
| `리딩노트` 포함 | [`tone-note.md`](tone-note.md) | 원문 어투 존중 (교정만) | aiwitness 번역/아티클 노트, 커뮤니티 인기글 단상 모음 |
| `작업노트` / 그 외 / 미지정 | [`tone-tech.md`](tone-tech.md) | 친근한 해요체 (~해요/~거든요) | 만들고 부순 기록 — 황견적 개발일지, fmkorea 개발일기 연재분 |

분류할 드래프트는 `drafts/<slug>/index.md` (git 미추적 작업 폴더) 상단에 카테고리를 미리 기입합니다:

```yaml
---
categories: ["에세이"]
series: ["이세계표류기"]   # 연재물일 때만. series_order: N 로 회차 지정
series_order: 2
---
```

미지정 시 기본값은 `작업노트`(해요체)입니다.

## 게시 정규화 (`scripts/normalize.py`)

퇴고를 마친 드래프트는 기계적(non-AI) 게시 단계로 조립합니다 — CI가 아니라 로컬에서 실행하고 결과를 커밋합니다:

```bash
python3 scripts/normalize.py                          # drafts/ → content/posts/
python3 scripts/normalize.py --single drafts/<slug>/index.md   # 단일 파일 미리보기
```

동작 계약:

- **본문 불변** — 단 하나의 예외: 선두 h1(#) 라인은 기계적으로 제거 (프론트매터
  title이 대신함). 그 외에는 바이트 단위로 보존.
- **프론트매터**: 기존 값 우선. 비어있는 필드(title/description/tags/date/categories/draft)만
  휴리스틱으로 채움 — 채워진 값은 **리뷰용 placeholder**이며 필드마다 `auto-filled` warning이
  남습니다. 위 SEO 규칙(description 150–160자 등)을 만족하는 최종 문안은 퇴고에서 확정. AI 호출 없음.
- 페이지 번들 생성·에셋 복사·`draft: true` 기본값 등 배관 수행. dot-엔트리(`.omc`, `.DS_Store` 등
  런타임·에디터 상태)는 어느 깊이에서도 복사하지 않습니다.
- `content/posts/<slug>/`가 이미 존재하는 slug는 **스킵** — 게재본은 사람이 리뷰·교정하는
  작업물이므로 덮어쓰지 않습니다. 재조립은 `--force <slug>`로만.
- 처리 대상은 `drafts/<slug>/index.md` 1단계 번들만 — 보류·완료된 원고는
  `drafts/archive/<slug>/`로 내려 기본 실행 대상에서 제외합니다.

## 공통 구조 규칙

### 제목

- h1(#)은 프론트매터 title로 대체, 본문에서 사용 금지
- h2(##)부터 시작

### 코드 블록

- 언어 태그 필수 (```python, ```bash 등)
- 코드 앞에 한 줄 설명
- 코드 뒤에 결과나 핵심 포인트 설명
- 긴 코드(30줄+)는 핵심 부분만 발췌하고 전체는 링크 또는 접기

## SEO 공통 규칙

### 프론트매터 필수 필드

```yaml
title: "글 제목 (60자 이내 권장)"
description: "글 요약 (작성 규칙은 문체 가이드별로 다름)"
tags: ["관련", "키워드", "목록"]
categories: ["작업노트"]  # 또는 ["에세이"], ["리딩노트"], ["특허"]
date: 2026-04-01
```

### tags 규칙

- 소문자 영문 또는 한글
- 3-7개 범위
- 너무 일반적인 태그 지양 ("개발", "코딩")

### description

- 문체 가이드별 규칙을 따름: 기술 글은 150-160자 SEO 요약([`tone-tech.md`](tone-tech.md)), 에세이는 한 줄 카피 허용([`tone-essay.md`](tone-essay.md))

## 퇴고 적용 규칙

퇴고 시 이 공통 가이드 + 해당 문체 가이드를 기반으로:

1. **어투 처리**: 문체 가이드에 따름 — 기술 글은 해요체로 변환, 에세이는 서술체 유지(교정만)
2. **구조 정리**: h1 제거(게시 정규화가 기계적으로 수행), h2부터 시작
3. **프론트매터**: 위 SEO 규칙에 따라 기입 — 비워두면 게시 정규화의 휴리스틱이 채움
4. **코드 블록 보존**: 코드 내용은 절대 변경하지 않음
5. **링크 보존**: 모든 링크와 이미지 경로 유지
6. **검색 친화 구조 (기술 글만)**: 검색 의도가 분명한 섹션 제목을 질문형으로 전환하고 직답을 앞세움 ([`tone-tech.md`](tone-tech.md)의 "검색 친화 구조" 참조). 에세이에는 적용하지 않음

### 변경하지 않는 것

- 코드 블록 내용
- URL/링크/이미지 경로
- 인용문 (blockquote) 내용
- 기존 프론트매터 값 (빈 필드만 채움)
- draft 상태
- 글의 문체 방향: 문체 가이드가 지시하지 않는 어투 변환 금지 (에세이를 해요체로 바꾸는 것 등)
