# 블로그 톤 & 형식 가이드

이 문서는 콘텐츠 정제 파이프라인이 외부 원고를 블로그 톤에 맞게 변환할 때 참조하는 기준입니다.

## 문체

### 기본 어투

- **~해요/~거든요/~인데요** 체 (친근한 설명체)
- 딱딱한 논문체(~하다/~한다) 금지
- 독자에게 말 거는 느낌: "이걸 보면 아시겠지만", "한번 해볼까요?"

### 좋은 예 / 나쁜 예

| 나쁜 예 | 좋은 예 |
|---------|---------|
| Docker는 컨테이너 기반 가상화 플랫폼이다. | Docker는 컨테이너 기반 가상화 플랫폼이에요. |
| 본 문서에서는 네트워킹을 다룬다. | 이번 글에서는 네트워킹을 다뤄볼게요. |
| 상기 방법을 적용하면 된다. | 위 방법을 적용하면 돼요. |
| 필자는 이 방식을 선호한다. | 저는 이 방식을 선호해요. |

### 금지 표현

- "본 문서", "상기", "하기" 등 공문서체
- "필자" → "저"로 대체
- 불필요한 경어 중첩 ("~하시겠습니다" 등)
- 영어 원문 번역투 ("그것은 ~이다", "~하는 것은 중요하다")

## 구조

### 글 구성

```
## 제목 (핵심을 담은 한 줄)

도입 (1-2문단): 왜 이 주제가 중요한지, 이 글에서 뭘 다루는지

## 본문 섹션 1
설명 + 코드/예시

## 본문 섹션 2
...

## 마무리 (선택)
핵심 요약 또는 다음 단계 안내
```

### 제목 규칙

- h1(#)은 프론트매터 title로 대체, 본문에서 사용 금지
- h2(##)부터 시작
- 제목은 명사형 종결 ("Docker 네트워킹 설정") 또는 의문형 ("왜 gRPC를 써야 할까?")

### 코드 블록

- 언어 태그 필수 (```python, ```bash 등)
- 코드 앞에 한 줄 설명
- 코드 뒤에 결과나 핵심 포인트 설명
- 긴 코드(30줄+)는 핵심 부분만 발췌하고 전체는 링크 또는 접기

## 독자 수준 태깅

글마다 독자 수준이 다를 수 있으므로, 프론트매터에 `level` 필드를 추가합니다:

| level | 대상 | 설명 스타일 |
|-------|------|------------|
| `beginner` | 주니어/입문자 | 용어 풀이 포함, 배경 설명 충분히 |
| `intermediate` | 중급 개발자 | 기초 생략, 실무 관점 중심 |
| `advanced` | 시니어/전문가 | 트레이드오프, 깊은 분석 중심 |

## SEO 규칙

### 프론트매터 필수 필드

```yaml
title: "검색에 노출될 제목 (60자 이내 권장)"
description: "글 요약, 검색 결과에 표시됨 (150-160자)"
tags: ["관련", "키워드", "목록"]
categories: ["기술"]  # 대분류
date: 2026-04-01
```

### description 작성 규칙

- 글의 핵심 가치를 한 문장으로
- "이 글에서는 ~를 다룹니다" 패턴 금지 → 구체적 내용 요약
- 나쁜 예: "이 글에서는 Docker를 설명합니다"
- 좋은 예: "Docker 브릿지 네트워크와 오버레이 네트워크의 차이점, 실무 설정 방법을 정리했어요"

### tags 규칙

- 소문자 영문 또는 한글
- 3-7개 범위
- 너무 일반적인 태그 지양 ("개발", "코딩")
- 구체적 기술명 우선 ("docker", "kubernetes", "gRPC")

## 정제 파이프라인 적용 규칙

정제 시 이 가이드를 기반으로:

1. **어투 변환**: 격식체/논문체 → 친근한 설명체
2. **구조 정리**: h1 제거, h2부터 시작, 도입부 보강
3. **프론트매터 생성**: 위 SEO 규칙에 따라 자동 생성
4. **코드 블록 보존**: 코드 내용은 절대 변경하지 않음
5. **링크 보존**: 모든 링크와 이미지 경로 유지

### 변경하지 않는 것

- 코드 블록 내용
- URL/링크/이미지 경로
- 인용문 (blockquote) 내용
- 기존 프론트매터 값 (빈 필드만 채움)
- draft 상태
